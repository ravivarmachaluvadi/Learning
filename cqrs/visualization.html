Ledger & Chalkboard

A shop records every sale in one guarded ledger (the write side — rules enforced, one entry per sale, an event per entry). A clerk copies new events onto chalkboards (the read side — one board per question) whenever they get to it. Queries read only the boards — instantly, but the boards run behind the ledger. Place orders, slow the clerk down, break the clerk's habits, and watch what queries see. The stories on the left narrate the important scenes.

What just happened

Rules this page uses: the clock ticks continuously while "Run clock" is on; the clerk copies one event per N ticks (the speed slider — production projectors are fast, but never instantaneous; the slider exaggerates reality so you can see it). "Careless" copying adds revenue without checking whether the event was already applied — harmless until "Redeliver the feed", which every real at-least-once feed eventually does on its own. The verdict compares each board against the ledger's own truth, which the page computes on the side — in production nobody has that luxury, which is exactly why idempotency and rebuilds matter.
