ZooKeeper Atomic BroadcastThe Epoch Ledger

Five servers keep one shared list of changes. One of them — the primary — is the only one allowed to write, and every change it writes gets stamped with a two-part serial number: epoch.counter. Epoch says which primary wrote it; counter says which change of that primary's it was. The whole protocol exists to guarantee one thing: every server ends up with the same list, in the same order, with no gaps — even when the primary dies mid-sentence. Kill servers, tear the network, and watch whether that holds.

How to read this picture

Dashed = written down, not yet finalThe server has the change on disk but has not been told it counts. A client asking about it must not be told it happened.
Solid = committedDelivered to the application. It can never be removed, and every other server must eventually have it too.
Hatched = thrown awayA new primary told this server to delete it. Only ever happens to changes that were never committed anywhere.
Colour = which primary wrote itOne colour per epoch. A colour change in the ledger is a change of management.

A teaching model of ZAB, the protocol inside Apache ZooKeeper. It is faithful about the parts this page is teaching — the two-part zxid, the four phases, quorum acknowledgement, DIFF/TRUNC/SNAP synchronisation, epoch rejection, and the NEWLEADER round that commits an inherited history. It simplifies elsewhere: real Fast Leader Election runs several rounds of notifications with back-off, real servers fsync to a transaction log before acknowledging, and real snapshots are fuzzy. Each simplification is named in the lab's README.
