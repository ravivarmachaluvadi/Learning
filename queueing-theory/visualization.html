Guess first, then run it

Each one asks you to commit before it runs. Being wrong is the point — the ones people get wrong are 1, 6 and 7.

One arrival stream, one line, one or more servers, in a discrete-event simulator with a seeded generator, so every run is reproducible. It was checked against closed-form results before being used to teach anything: Little’s Law (L = λW) to within 0.01 jobs, M/M/1 waiting times to within 2% from 50% to 95% busy, M/D/1 at exactly half of M/M/1, D/D/1 at zero, Erlang-C for four pooled servers to the digit, and Kingman’s approximation to within 5% across eight variability combinations.

Two things worth naming. One: real service times get slower as load rises (cache pressure, garbage collection, lock contention), which this simulator does not model — so every number here is the optimistic case, and the real cliff is sharper and arrives earlier. Two: the scenarios run for 30–90 simulated minutes so they finish while you wait, and a 99th percentile measured over that span wobbles by 10–20% between runs. The lab’s README quotes four-hour runs averaged over several seeds, so its tail figures are slightly lower and closer to theory. The averages agree closely either way.
