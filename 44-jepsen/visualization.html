The Falsifier

Jepsen does not check whether a database gave the right answer. It records everything that happened, then searches for any story that could explain it. When no story exists, the database's claim is false. This page lets you run that search — and shows you the one thing that quietly breaks most home-made versions of it.

Recorded runs against FerrousDB

Each is a real transcript from a test: four client processes reading and writing one counter, x, which starts at 0. Pick one. FerrousDB is fictional; every behaviour here is modelled on a published finding in a real system.

Three judges, one transcript

All three run the identical search on the identical history. They differ only in how they read an :info. Where they disagree, that disagreement is the lesson.

Why the judge runs out of time

Here the history is k writes that all overlap each other, followed by a read that no ordering can satisfy — so the search must try everything before giving up. Drag k and watch the cost. The pruning rule is the heart of the WGL algorithm Knossos uses: if you have already explored a state with the same set of remaining operations and the same register value, there is nothing new down this path.

Recorded transactional runs

Now the claim is serializability, and operations are grouped into transactions. Knossos cannot help: it searches for an order, and transaction orderings do not decompose by key. Elle looks for a cycle instead.
