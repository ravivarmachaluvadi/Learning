The Honest Clock

A land registry has two offices. A deed is filed in the first, the clerk hands over a receipt, and only then — after a telephone call — is a mortgage filed in the second. Any human would say the deed came first. The two office clocks disagree, so the register says otherwise, and someone owns a house they sold. Below is that story running as a database. The horizontal axis is real, physical time — the thing no machine in a distributed system can actually see, and which you can see because you are outside it.

Every transaction is drawn twice: a bar showing when it really happened, and a diamond showing the timestamp the system gave it. When two diamonds are in a different order from their bars, the database has recorded a history that did not happen.

The rules this simulator follows

So that you can check that the numbers mean what the page claims they mean. Times are in milliseconds from an arbitrary origin. Two Paxos groups, G1 (leader in Northgate) and G2 (leader in Southgate), plus a Singapore replica of each.

  1. The clock. For a region with true offset o and error bound ε, TT.now() at real time t returns [t+o−ε, t+o+ε]. The clock is honest when |o| ≤ ε, which is the only thing TrueTime actually promises. Scenario 4 breaks that promise on purpose.
  2. Choosing the timestamp. A leader sets s = max(TT.now().latest, s_max + 0.001) and advances s_max to s. The s_max term is the monotonicity invariant; it is per group, and groups never consult each other.
  3. Commit wait. With it on, the leader acknowledges only once TT.after(s) — i.e. once t + o − ε > s. With it off it acknowledges as soon as Paxos is done. Paxos replication is a fixed 2 ms here; a real one is 5–10 ms locally and far more across continents.
  4. Reads. A read-only transaction gets s_read = TT.now().latest (or LastTS() — the group's last commit timestamp — in single-group mode), then goes to the chosen replica. That replica answers only when s_read ≤ t_safe, where t_safe = min(t_safe_paxos, t_safe_TM): the highest write it has applied, and one tick below the lowest prepare timestamp of any undecided two-phase commit.
  5. Replication lag. A write committed at real time t reaches a replica at t + lag. The Singapore lag is a knob.
  6. The verdict. After every step the page re-checks, over all pairs of committed transactions: if T₁ was acknowledged before T₂ started, is s₁ < s₂? It also checks every completed read against every transaction acknowledged before that read began. Either check failing turns the banner red.
  7. What is compressed. Leader leases are 10 seconds in production and 40 ms here; the MinNextTS cadence that lets idle groups serve reads is 8 seconds in production and 60 ms here. Both are labelled where they appear. Nothing else is scaled.
  8. What is left out. Wound-wait aborts, the lock table, fine-grained safe time, real Paxos, persistence, schema changes, and every optimisation in the 2017 SQL paper. This page is about one thing: where a timestamp comes from and what it costs.
