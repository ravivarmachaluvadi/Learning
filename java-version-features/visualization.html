The Java Departure Board

Java 9 took three and a half years and arrived carrying 91 changes at once. Java 10 shipped six months later with 12. Everything Java does now — the six-month train, preview features, LTS — exists to make sure the first number never happens again. This board lets you watch the machinery run.

Every Java release since 2018 departs in March or September, ready or not. Set where you are and where you want to get to — the numbers below are the size of the crowd you have to get through the ticket barrier.

Java 9 shipped 91 changes. How many did Java 10 ship, six months later?
The answer is the whole argument for the release train.

12. And that is the point, not a disappointment. Java 9 was not big because the team was productive; it was big because 41 finished features sat waiting on one unfinished one for three and a half years. Java 10 shipped what was ready on the day it said it would, and 12 changes is a delta you can absorb in normal maintenance rather than a project you have to schedule.

What happened, in order

Pattern matching for switch needed five releases. The Vector API has been incubating for ten. What does a very long stay in the pipeline usually mean?
Step to release 25 and look at the Vector API row before answering.

It is blocked on something else. The Vector API's own proposal says it will stay in incubation until Project Valhalla delivers value types, because the API is designed around value semantics the language does not have yet. Finalising now would freeze a design against a language about to change underneath it.

So a long stay is a signal about dependencies, not quality. Read the JEP text — it usually says outright what it is waiting for. Compare with string templates, which left the pipeline after two previews by being withdrawn: that is what a design failure actually looks like, and it looks nothing like ten patient incubations.

Every byte string and error message on this page was produced on OpenJDK 25.0.4 while this lab was built. The cross-version cases are derived from the same two rules the JVM applies: minor == 65535 requires --enable-preview, and a preview class file's major version must match the running JVM exactly.

You build a library on JDK 25 with --enable-preview and publish the jar. A colleague on JDK 26 adds it as a dependency. What happens?
Set the controls to build on 25 with the flag, then run on 26.

Refuses to load, flag or not. Normal class files are forward compatible — Java 8 bytecode still runs on JDK 25, and that is Java's strongest promise. A preview class file is deliberately exempt: its major version must match the running JVM exactly, so a file built on 25 runs on 25 and nowhere else.

That is not a bug to work around. It is the mechanism that makes preview features safe to ship at all — it makes it impossible for an impermanent feature to quietly become load-bearing infrastructure inside somebody else's dependency tree. The practical rule: never publish preview-compiled artifacts, and only use preview features in an application you rebuild on every JDK bump.

Upgrade pain is not mysterious — it is a known list, and the platform warned you about almost all of it years in advance. Pick your jump. The ones with a red edge fail silently, and those are the ones that reach customers.

You are moving from 8 to 25. Which single hazard is most likely to reach a customer?
Not the one that costs the most time — the one that gets past you.

The charset default. The other two are painful and they are found by compiling and starting the application — they cost you an afternoon and they are impossible to miss.

JEP 400 throws nothing. Text that used to decode one way now decodes another way, and the only thing that catches it is a test asserting on output content. If no such test exists, it ships, and it surfaces two weeks later as corrupted names in a report.

The implication for how you test an upgrade: compiling and booting on the new JDK proves almost nothing. Run your full behavioural suite on the next JDK in a non-blocking CI job, continuously, starting long before you plan to move.
