Carriers & Continuations

A server has many tasks (requests) but very few OS threads ("carriers" — think waiters in a restaurant). Each task alternates between computing (needs a carrier) and waiting for a database (needs nothing — if it can step off its carrier). This page simulates how the three worlds Java has lived in handle that. Start with a story button; every event is narrated below.

Rules this page uses (so nothing looks like magic): the task at the front of the queue mounts the lowest-numbered free carrier — real JVMs use work-stealing queues, but the principle is identical. "Wait" stands for any blocking call: a JDBC query, an HTTP call, Thread.sleep. Each task here computes, then waits, then computes again (parse → database → respond). In the JDK 21 world every wait happens inside synchronized, the worst case that JEP 491 later fixed. Change any slider — the point of this page is that the outcome, not the diagram, is the lesson.
