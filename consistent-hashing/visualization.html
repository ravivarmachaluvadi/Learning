The Clockwise Rule

You have some data and some machines, and you must decide which machine holds which item. The obvious rule — hash(item) % numberOfMachines — works perfectly until the number of machines changes, and then it moves almost everything. Below is the fix. The ring — every machine and every item on one circle

The circle is the whole range of hash values. Each machine sits at several positions on it (the thick coloured bands). Each item is a small dot at its own hash position, and it belongs to the first machine clockwise from where it landed — so a dot is coloured like the band ahead of it. Click any dot to see its walk.

What this model simplifies. Real rings use a 64-bit hash space; this page uses 32-bit so the numbers fit on screen, and the principle is identical. Real deployments use 100–200 positions per machine — the slider stops at 120 only so the drawing stays legible. Everything else here — the clockwise rule, virtual positions, replication onto the next distinct machines, and the fact that the machine count appears nowhere in the lookup — is exactly how the real thing works.
