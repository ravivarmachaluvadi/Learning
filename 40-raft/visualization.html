Six things that can go wrong

Each card resets the cluster, asks you to commit to an answer, then runs the scenario with narration. Being wrong here is the point — it is how the surprising rules stop being arbitrary.

A server's job
  • Leader — the only one that takes writes
  • Candidate — asking to be leader
  • Follower — copying the leader
  • Crashed — sends and hears nothing
A slot in the log
  • written down, not yet safe — can still be deleted
  • committed — a majority has it, it can never change
  • colour = the term the entry was created in
In the band above
  • a vote being asked for, or given
  • log entries, or the reply to them
  • a dot travelling = a message that has not arrived yet
Timings are shortened so you can watch them: election timeout 15–30 ticks, heartbeat every 5. A real cluster uses roughly 150–300 ms and 50 ms. Everything else — the voting rule, the log consistency check, the commit rule — is the protocol as written in the Raft paper, with one simplification: this page does not model writing to disk, so a crash here loses only the in-memory bookkeeping, never the log.
