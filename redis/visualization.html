The One Thread

Redis holds your data in memory and runs every command to completion on a single thread, one at a time. That one sentence is the source of its best guarantee and its worst failure. Below is that thread. Send it work and watch what it does — and what everybody else does while it is busy.

What this model simplifies. Ticks are not milliseconds — they are just "one unit of the thread's attention", sized so you can watch. A real Redis executes most commands in a few microseconds and the network round trip usually costs more than the command does. Real Redis also does some work off the main thread (flushing to disk, freeing large values, and since version 6, reading and writing sockets) — but the part modelled here, the part that touches your data, really is one command at a time. Everything else on this page — lazy and sampled expiry, sampled eviction, write-ahead logging, asynchronous replication — mirrors how Redis actually behaves.
